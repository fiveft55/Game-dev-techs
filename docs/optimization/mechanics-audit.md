# 11. Audit of the current 51 mechanics

This is a source-level cost audit of the current educational implementations, not a profiler report. Each row links to the actual Python code and the native contract. “Next experiment” means a candidate improvement, **not an optimization already implemented or benchmarked**. Native contracts sometimes expose a smaller operation or a different data structure; see [language conventions](../language-ports.md).

Complexity describes growth in the named input, ignoring ordinary constant factors. Hash/set costs are expected/average where stated. Python arbitrary-precision numbers, user callbacks, allocations, output size and native interfaces can add costs. Fixed-size math is not zero time. C uses a configured fixed-capacity buffer; changing capacity/ABI is a separate engineering decision.

## What is not implemented by this handbook

No object pool, new broad-phase tree, ECS storage, job scheduler, renderer, streaming layer, network transport or optimized native hash table was added. This update documents how to evaluate those options. Existing behavior/tests remain the baseline. Use the [benchmark recipe](10-benchmarking.md) and preserve the per-mechanic correctness contracts before promoting an experiment into the library.
