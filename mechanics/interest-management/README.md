# Server-side spatial interest filtering

<!-- BEGIN PLAIN ENGLISH -->
## Plain-English explanation

Send a player only nearby objects they are allowed to know about.

1. The trusted server decides which objects this player may see.
2. Check how far each allowed object is from the player.
3. Keep only the ones inside the chosen range.
4. Return their IDs. This does not encrypt data or decide authorization by itself.

See [PORTS.md](PORTS.md) for actual inputs, outputs and a worked example. The [beginner guide](../../docs/beginner-guide.md) explains common coding words.
<!-- END PLAIN ENGLISH -->

## Mechanic and algorithm

Filter entities by a server-owned access decision and squared distance from an observer. Return IDs only; serialization should include only explicitly permitted fields. Apply authorization before sending any entity data.

## Assumptions and limits

Linear scan and circular 2D range, not sharding, authentication, occlusion, or anti-cheat. The allowed predicate must enforce game-specific secrecy; nearby does not mean authorized.

Tune the rules for your game and extend the tests before integrating. Educational coverage is not a full genre implementation or a production-readiness guarantee. The original Python API is preserved. Eight additional native kernels are available; see the portable contract for their API and scope differences.
